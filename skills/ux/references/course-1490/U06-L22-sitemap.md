## What a site map shows

Anchor: 1490 · U6 · L22 · 00:00–00:50

Site maps (*mapas del sitio*; *sitemaps*) help us organize content in a digital product. In this lesson we’ll learn to make them quickly and effectively. A site map is a hierarchical diagram that shows the structure of a website or an application.

Here is a typical example. The home page is at the top, with the main menu items below it: promotions, a search box, about us, blog, shareholders and investors, and contact. Under those items we can show the content of each section and how the sections link to one another. This is the traditional way to represent a site map.

## Why make a site map

Anchor: 1490 · U6 · L22 · 00:50–01:12

There are several advantages to designing a site map for our digital product. It helps us understand and define the navigation. It also lets us estimate the amount of content we will need—or, based on the content we already have, estimate the size of the website. Without a site map, we might forget content or a section, affecting the budget or giving us an unpleasant surprise.

## Co-designing the map with a team

Anchor: 1490 · U6 · L22 · 01:12–02:20

This is how we should make site maps: in an ideation session with clients or stakeholders (*partes interesadas*), deciding together what the map should contain. Then we can test the navigation with users. An internet search will show you many tools for making site maps, but I recommend always making them by hand first, then tidying them up if necessary once they are finished and agreed. We currently use Octopus when we need a final deliverable, but we usually work by hand. We have also used MindMeister (captions: *mi maester*), which has a free version and helps us work quickly.

At Elastic Heads, we work on site maps with clients or stakeholders using a Google Docs document. We organize information with numbered or bulleted lists and share the document with other team members so we can make decisions quickly. Our design team includes programmers and business people, so we should not require complex tools when designing, for example, this site map.

## Organizing a reading app

Anchor: 1490 · U6 · L22 · 02:20–03:48

Here is another example using sticky notes. We’ll make a site map for our reading app and decide how to organize the content in its lower navigation bar. The home section will show a feed with news, challenges, user updates, or even updates from the app itself. In Discover, we’ll have book recommendations, popular books, and themed collections, such as horror and fantasy.

In My Reading, we’ll include the book I am currently reading, my library with all my books and any highlights and comments I have made, the books I have lent, and the next books I want to read. We’ll add statistics about reading pace or speed, reading challenges in the app, and an option to add books. Although “Add book” is at the end of the list, we’ll put it somewhere prominent so that it is easy to find.

Finally, there will be a User section. I have represented it with a circle because a user’s photo is always shown inside a circle. The squares represent the app’s icons (captions: *los parados*). In the User section we would include the recommendations and comments I have written, notifications when someone replies to or rates a recommendation or comment, and the app settings.

This is a very quick way to organize the content of our digital product and work on it with the rest of the team, clients, or stakeholders.

## From outline to a cleaned-up diagram

Anchor: 1490 · U6 · L22 · 03:48–04:14

Once we have started working on the app sketches, we can tidy the map if needed. I used MindMeister (captions: *SimMeister*), but you can use any program for designing a site map. Creating a site map is an important step in user-centered design (captions: *diseño central al usuario*): it helps ensure that content is where users expect to find it. We can validate the site map with users by asking them to find things within the structure.

## Balancing user experience and SEO

Anchor: 1490 · U6 · L22 · 04:14–04:45

One important issue we have encountered over the years is whether to prioritize user experience (*experiencia de usuario*) or search engine optimization (SEO; *optimización para motores de búsqueda*). For many years, when organizing information, SEO was prioritized. For example, a product name might be put in the site’s main navigation. That made navigation more confusing but helped the site rank well in search engines. Ideally, we should talk with the SEO team so that both sides are happy with the project’s result.

## Recommendations for making a site map

Anchor: 1490 · U6 · L22 · 04:45–05:28

Here are a few recommendations. Always make site maps before starting to design wireframes (captions: *wild friends*). Often, if the navigation is very simple, we can make a prototype with our screens instead of drawing the site map. It is optional. I recommend making site maps when there is a lot of content or the navigation may be complex. And I insist that we use tools stakeholders can use, rather than design software such as Illustrator or Photoshop.
