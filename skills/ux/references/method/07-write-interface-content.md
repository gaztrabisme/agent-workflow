# Stage 7: Write interface content

## Reader and scope

**Reader:** a team writing and reviewing interface words in the context of a user task. **Scope:** create a coherent product voice and specific content for navigation, onboarding, empty states, notifications, errors, and actions.

## First idea, stated as the rule

- Start from the user's goal and draft both sides of the exchange as a conversation. Use it to notice missing questions, options, and next steps before converting the dialogue into interface copy. (798 · U3 · L09 · 02:40–06:25)
- Write microcopy that is clear, concise, useful, and human: explain what is happening in understandable words, get to the point, help with the next action, and respond to the person's context. (798 · U3 · L09 · 06:25–08:48)
- Keep the product's voice consistent while adjusting tone to the user's situation. Map a small set of representative interactions in sequence rather than assigning a tone to every string in isolation. (798 · U3 · L10 · 00:00–02:03; 798 · U3 · L10 · 04:22–08:40)
- Put important information in headings and opening words, and split dense copy into scannable pieces. The course uses reading patterns to explain why people may miss information lower in a page. (798 · U3 · L08 · 03:42–06:38; 798 · U3 · L08 · 06:38–08:38)

## Match the message to the interaction

| Interaction | Include | Source |
|---|---|---|
| Onboarding | What the product does, its value, how to use it, and a timely next step | 798 · U4 · L11 · 01:14–03:22 |
| Empty state | Where the person is, why it is empty, what will appear, and a relevant action | 798 · U4 · L11 · 07:26–10:30 |
| Notification | Context, user benefit near the beginning, and what to do next | 798 · U4 · L12 · 00:00–03:43 |
| Error | Where it happened, what happened, and a way to recover; do not blame the user | 798 · U4 · L12 · 05:50–10:41 |
| Button | A short active label that names the action that will actually happen | 798 · U4 · L12 · 10:41–14:02 |

## Failures

**Problem: a message says there is an error but leaves the user at a dead end.**
- **The failure:** the message omits the context, what happened, or a recovery option. (798 · U4 · L12 · 05:50–10:41)
- **The fix:** put the explanation where the error occurred and offer a next action that the interface can perform. (798 · U4 · L12 · 05:50–10:41)

**Problem: playful copy hides an action.**
- **The failure:** the label does not let the person predict what a choice will do. (798 · U4 · L12 · 10:41–14:02)
- **The fix:** use a brief, active verb and make alternatives explicit. (798 · U4 · L12 · 10:41–14:02)

## Check before moving on

**T7 — Interaction copy:** each message fits its state and goal; errors explain the issue and recovery; labels describe actual behavior; the copy uses understandable, useful language.

**T8 — Voice and tone:** voice is coherent across the flow; tone fits the situation and does not mock or blame the person.

**Practice the teacher sets:** write a welcome conversation, a voice-and-tone “this, but not this” list, onboarding, an empty screen, notifications, errors, buttons, and account-creation content. See [798 · U3 unit](../course-798/U03-unit.md) and [798 · U4 unit](../course-798/U04-unit.md).
