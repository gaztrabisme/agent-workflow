# Speaker-script pass

Before a deck is shown, script it and find what it says twice.

## Script order

Walk the deck from the first slide to the last, in order. For each slide, read its text and visuals and write what the presenter says, with the script so far in hand. Either one agent walks the whole deck, or each slide's agent receives the script of every slide before it. Never script slides in parallel without the earlier script: repetition is only visible against what was already said.

The source practice is to write speaking notes with the important points for each slide and to practise aloud, which "forces you to articulate the transitions between slides that sometimes trip up presenters." [book:storytelling-with-data], chapter one the importance of context > What

## Repeat marking

A reviewer who did not write the script marks each sentence "new" or "repeats slide N".

Keep the one main message the deck repeats on purpose. People are more likely to remember what has been repeated, so the goal and the decision are planned to recur through the conversation. [book:articulating-design-decisions], Chapter 3. Design the Meeting > Optimize for Memory

List every other repeat as a cut candidate with its slide numbers. The deck owner decides which to cut.

## Script handling

The script is internal. It does not go into the deck file unless the owner asks for speaker notes.
