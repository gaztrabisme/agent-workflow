# Measurement

Use the project’s existing commands where possible. Thresholds below are either a sourced standard/metric or an exact test outcome; never substitute an invented score for a product requirement. (derived: [book:web-performance-engineering], “Setting Up Performance Budgets and Alerts”; [render-kit/AGENTS.md](../../../../tools/render-kit/AGENTS.md).)

| ID | Code check or vision question | Pass threshold and source |
|---|---|---|
| T1 | Brief review: inspect the brief and compare it with route/state inventory and acceptance checks. | Every required field in T1 is present; fields are derived from the project context recorded in [src:platform-apps/report.md], “Verdicts,” and [book:css-in-depth-2e], “7 Responsive design.” |
| T2 | Check live Baseline status or MDN compatibility for each feature that affects a core interaction; record the target browser set. | No core task depends on a feature outside the target without a tested fallback; target definition follows [book:web-dev-baseline], “Baseline,” and current definitions at [doc:https://web.dev/baseline/]. |
| T3 | Use Playwright `getByRole`/`getByLabel` assertions on primary actions and fields; inspect the resulting DOM and accessibility tree when a locator or name is unexpected. | Every primary action and field has the intended semantic role and a unique useful name. This skill does not prescribe a separate HTML validator. Source: [book:playwright-docs], “Frame.getByRole.” (derived: dogfood 2026-10-02, F6) |
| T4 | Toggle each disclosure, checkbox, tab, or selection; assert visible state and ARIA state in a Playwright accessibility snapshot. | Every tested state agrees; no stale or contradictory state. Source: [src:agent-ready-web/report.md], “F4. The accessibility tree as the agent interface”; [book:wai-aria-apg], “WAI-ARIA Roles, States, and Properties.” |
| T5 | Run viewport screenshots at the brief’s smallest, typical, and widest widths, including 320 CSS px; query page scroll width and element bounds, and inspect SVG chart text at the narrow width. Vision: can text be read without clipping and is the task order clear? | No unintended horizontal page overflow at 320 CSS px for vertical content, subject to WCAG exceptions; chart text stays at least at body size or the chart uses an allowed scroll region. Threshold: [book:wcag-22], “Success Criterion 1.4.10 Reflow”; layout procedure: [book:css-in-depth-2e], “7 Responsive design.” (derived: dogfood 2026-10-02, F9) |
| T6 | Test the feature-enabled and fallback mode through a browser target or by disabling the feature; assert the primary task still works. | All primary interactions work in both modes; exact threshold is the task contract. Source: [book:css-in-depth-2e], “1.5.1 Using the cascade for progressive enhancement”; current status source: [doc:https://web.dev/baseline/]. |
| T7 | Run the project’s version-matched lint, type-check, and build commands. | Exit status 0 and no new framework/compiler errors; version discipline: [src:platform-apps/report.md], “F5. Principles that transfer across frameworks.” |
| T8 | Playwright scenarios for loading, empty, success, error, and confirmation states; assert their text, actions, next result, and that every other state region is hidden or absent. | Every in-scope state is reachable, exactly its own state content is visible, and it has a valid next action or terminal outcome; exact coverage comes from the brief. (derived: the scenario check applies React's guidance to avoid contradictory state and UC5d's confirmation requirement for high-stakes actions.) [book:react-dev], “Choosing the State Structure”; [src:agent-ready-web/report.md], “UC5d — Extraction review interfaces.” (derived: dogfood 2026-10-02, F5) |
| T9 | Use render-kit contrast results or a WCAG contrast calculation on each relevant text/background pair. | 4.5:1 normal text; 3:1 large text, subject to SC 1.4.3 exceptions. Source: [book:wcag-22], “Success Criterion 1.4.3 Contrast (Minimum).” |
| T10 | Tab and Shift+Tab through the route; open/close overlays; after actions that disable/remove themselves, assert the next focus destination. Vision check: focus remains visible and unobscured. | Every primary control is keyboard reachable; focus is visible and not entirely obscured. Source: [book:wcag-22], “Success Criterion 2.4.7 Focus Visible”; [book:wcag-22], “Success Criterion 2.4.11 Focus Not Obscured (Minimum).” (derived: dogfood 2026-10-02, F10) |
| T11 | Query pointer-target bounding boxes for relevant controls. | At least 24 × 24 CSS px unless a documented SC exception applies. Source: [book:wcag-22], “Success Criterion 2.5.8 Target Size (Minimum).” |
| T12 | Run the available axe or equivalent analyzer, then manually navigate with keyboard and inspect the tree. | Zero unresolved violations in the tested ruleset; manual results remain a separate record. Automated tools do not establish full conformance: [src:platform-apps/report.md], “F8. Quality: accessibility, testing, performance”; [book:playwright-docs], “Accessibility testing.” |
| T13 | Use the scripted Playwright lab procedure in [performance.md](performance.md) for internal diagnostics; use field web-vitals/analytics when available. | For field CWV, p75 LCP ≤2.5s, INP ≤200ms, and CLS ≤0.1. [doc:https://web.dev/articles/inp]; [book:web-dev-baseline], “Defining the Core Web Vitals metrics thresholds.” Lab interaction-to-paint timings are proxies, not INP. Otherwise use the product owner’s named budget. (derived: dogfood 2026-10-02, F7) |
| T14 | Playwright getByRole assertions and state assertions for each primary journey; inspect the accessibility tree for mismatched roles, names, or states. | Every primary action is locatable by role/name and each interaction reaches its expected state. Source: [src:agent-ready-web/report.md], “UC7 — Coding agents that must see and check what they built”; [book:playwright-docs], “Frame.getByRole.” |
| T15 | (derived: checking the browser result tests the typed alternative recommended in [src:agent-ready-web/report.md], “F4. The accessibility tree as the agent interface.”) Verify that each drag or slider interaction has a typed alternative. | Every drag or slider interaction has a typed alternative. [src:agent-ready-web/report.md], “F4. The accessibility tree as the agent interface.” |
| T16 | When an optional web tool is implemented, test absent API, unauthorized caller, cancellation, malformed input, and confirmation denial. | The ordinary UI works without the API; unauthorized/invalid calls have no side effect; a denied confirmation leaves data unchanged. Source: [src:agent-ready-web/report.md], “F1. WebMCP: tools that a web page declares for in-browser agents”; [src:agent-ready-web/report.md], “F6. Security of agent-facing interfaces.” |
| T17 | Run render-kit check for each key route/state and inspect every fail, skipped, or incomplete entry. | Zero unresolved fail; every skipped or incomplete item has a stated reason and owner. Source: [render-kit/AGENTS.md](../../../../tools/render-kit/AGENTS.md). |
| T18 | Run render-kit brief with yes/no visual questions for hierarchy, wrapping, clipping, responsive fit, and state clarity; verify the answers file. | No unanswered “no”; unavailable judgments are marked not-judged and never counted as pass. Source: [render-kit/AGENTS.md](../../../../tools/render-kit/AGENTS.md). |
| T19 (redesign only) | Before redesign edits, audit the existing interface: run Lighthouse agentic-browsing and accessibility categories, fix names, labels, and native controls first, and use framework MCP servers. | Audit the interface before changing it. [src:agent-ready-web/report.md], “UC6 — Existing Angular and React codebases.” Greenfield: n/a. (derived: dogfood 2026-10-02, F15) |
| T20 (redesign only) | After redesign edits, rerun project checks and compare baseline and new renders at the same viewport; vision question: did the change preserve required behavior while fixing the finding? | All acceptance checks pass; each changed or regressed area is named. Threshold derives from the approved brief. [render-kit/AGENTS.md](../../../../tools/render-kit/AGENTS.md). Greenfield: n/a. (derived: dogfood 2026-10-02, F15) |
