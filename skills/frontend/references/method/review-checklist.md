# Review checklist

Each failed test returns to its named stage. A visual change returns through render-check even when its originating stage is elsewhere. (derived: [src:platform-apps/report.md], “Rule B: HTML first, then verify what renders”; [render-kit/AGENTS.md](../../../../tools/render-kit/AGENTS.md).)

| ID | Stage | Pass condition |
|---|---|---|
| T1 | Brief and baseline | Audience, task, routes, key states, content/data source, constraints, and acceptance evidence are recorded. (derived: this skill's field list is a project-level checklist; its audience/support-target prompt adapts the support-target guidance in [src:platform-apps/report.md], “Verdicts.” The section does not enumerate these fields.) |
| T2 | Brief and baseline | Browser/device target and support-sensitive features are identified; current feature status is checked before adoption. (derived: [src:platform-apps/report.md], “Rule A: choose the support target by who opens the output”; [doc:https://web.dev/baseline/].) |
| T3 | Structure and semantics | Heading hierarchy, landmarks, links, buttons, labels, and form relationships express their purpose in the DOM. [book:whatwg-html], “Semantics, structure, and APIs of HTML documents”; [book:wai-aria-apg], “Use ARIA Landmarks.” |
| T4 | Structure and semantics | ARIA roles and states are needed, valid, and synchronized with the visible state. [book:mdn-web-docs], “Before using ARIA”; [src:agent-ready-web/report.md], “F4. The accessibility tree as the agent interface.” |
| T5 | Layout and CSS | Layout follows project tokens and remains usable at the named viewport sizes without clipped text or unintended horizontal scrolling. (derived: [book:css-in-depth-2e], “7 Responsive design”; [book:wcag-22], “Success Criterion 1.4.10 Reflow.”) |
| T6 | Layout and CSS | Progressive enhancements leave a complete base interaction when unsupported. [book:css-in-depth-2e], “1.5.1 Using the cascade for progressive enhancement”; [doc:https://web.dev/baseline/]. |
| T7 | Components and state | Code uses the installed framework version and project conventions; build and type checks pass. [src:platform-apps/report.md], “F5. Principles that transfer across frameworks.” |
| T8 | Components and state | Each relevant loading, empty, success, error, and confirmation state gives accurate content and actions. (derived: the scenario checklist applies React's guidance to avoid contradictory state and UC5d's confirmation requirement for high-stakes actions.) [src:agent-ready-web/report.md], “UC5d — Extraction review interfaces”; [book:react-dev], “Choosing the State Structure.” |
| T9 | Accessibility | Applicable WCAG 2.2 AA criteria are checked; text contrast is at least 4.5:1 normal or 3:1 large, subject to criterion exceptions. [book:wcag-22], “Success Criterion 1.4.3 Contrast (Minimum).” |
| T10 | Accessibility | Keyboard users can reach and operate all primary actions with visible, unobscured focus. [book:wcag-22], “Success Criterion 2.1.1 Keyboard”; [book:wcag-22], “Success Criterion 2.4.3 Focus Order”; [book:wcag-22], “Success Criterion 2.4.7 Focus Visible”; [book:wcag-22], “Success Criterion 2.4.11 Focus Not Obscured (Minimum).” |
| T11 | Accessibility | Pointer targets meet 24 by 24 CSS pixels or a documented SC 2.5.8 exception applies. [book:wcag-22], “Success Criterion 2.5.8 Target Size (Minimum).” |
| T12 | Accessibility | Automated accessibility findings are resolved or documented and manual keyboard/tree review is recorded separately. [book:playwright-docs], “Accessibility testing”; [src:platform-apps/report.md], “F8. Quality: accessibility, testing, performance.” |
| T13 | Performance | Agreed lab or field budgets are met; if using field Core Web Vitals, p75 is LCP ≤2.5s, FID ≤100ms, and CLS ≤0.1. [book:web-dev-baseline], “Defining the Core Web Vitals metrics thresholds.” For INP, use a target of 200ms or less. [book:web-performance-engineering], “Setting Up Performance Budgets and Alerts.” |
| T14 | Agent-ready affordances | Primary actions are findable by role and accessible name, and state assertions reflect what the user sees. [book:playwright-docs], “Frame.getByRole”; [src:agent-ready-web/report.md], “F4. The accessibility tree as the agent interface.” |
| T15 | Agent-ready affordances | Each drag or slider interaction has a typed alternative. [src:agent-ready-web/report.md], “F4. The accessibility tree as the agent interface.” |
| T16 | Agent-ready affordances | Optional page tools are feature-detected, permission-scoped, and cannot bypass confirmation for consequential actions. [src:agent-ready-web/report.md], “F1. WebMCP: tools that a web page declares for in-browser agents”; [src:agent-ready-web/report.md], “F6. Security of agent-facing interfaces.” |
| T17 | Render and check | Every key route and state has a render-kit result; no fail remains unresolved and every skipped/incomplete result is reviewed. [render-kit/AGENTS.md](../../../../tools/render-kit/AGENTS.md). |
| T18 | Render and check | A vision reviewer answers concrete questions or the relevant dimensions are marked not-judged; no visual “pass” is inferred from code. [render-kit/AGENTS.md](../../../../tools/render-kit/AGENTS.md); [src:platform-apps/report.md], “Rule B: HTML first, then verify what renders.” |
| T19 | Audit-first redesign | Audit the existing interface before edits: run Lighthouse agentic-browsing and accessibility categories, fix names, labels, and native controls first, and use framework MCP servers. [src:agent-ready-web/report.md], “UC6 — Existing Angular and React codebases.” |
| T20 | Audit-first redesign | Findings have evidence, impact, an owning stage, and a regression check; changes preserve the project system unless a blocker justifies a change. [src:platform-apps/report.md], “F5. Principles that transfer across frameworks”; [src:graphics-motion/report.md], “6. Existing codebases.” |
