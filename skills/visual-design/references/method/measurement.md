# Measurement: code checks and vision questions

Reader: an agent verifying a render-kit render of an SVG or composed HTML artifact. The course mostly checks by arranging material and judging it visually; the numerical defaults below are chosen by this skill unless marked otherwise.

## Measurement contract

- Run render-kit checks before the visual-design measures. Use the HTML/SVG artifact and its render-kit output; do not measure an unrendered approximation when the final render is available.
- Mark the intended frame regions with data-rk-stage and identify the focal region with data-rk-focal. Declare intended grids, alignment anchors, negative-space targets, type levels, focal region and exceptions in the artifact or its review brief.
- Data attributes supply measurement regions, not semantic proof. A visual-weight centroid near the frame centre does not by itself prove balance; colour and meaning decisions belong to color-theory.
- The scripts/checks.py subcommands are grid, balance, space, scale and focal; the formulas and markup they consume are defined below.
- Run relevant code checks first. Vision review is done in a fresh context by a reviewer who can see the render. Without that review, record the vision result as not judged.

## Reporting

For every test state one of: **measured**, **vision-judged**, **not judged** or **skipped**. Give the actual reading for numerical checks. If a threshold is overridden, state the brief or domain requirement that replaces it. A visual measure estimates a property; it does not establish that the audience understands a design.

When these IDs appear beside color-theory checks in a report, prefix visual-design tests as VD-T1 through VD-T12; the checklist keeps its stable local T1–T12 IDs. (derived: run-2 dogfood, finding row 4's collision between visual-design and color-theory test IDs)

## Script inputs and formulas

`checks.py` consumes a render-kit PNG. `measure_boxes.mjs` records the stage, focal box, visible type sizes, grid boxes and occupied boxes by calling render-kit's own prepared Chromium page. Give it the same viewport, scale, animation time and render options used by `rk check`. The helper's JSON uses PNG-pixel boxes, a CSS-pixel stage size and the stage declarations below:

| Markup | Meaning |
|---|---|
| `data-vd-columns`, `data-vd-gutter`, `data-vd-margin` on the stage | Equal-column grid geometry in CSS px; gutter and margin default to 0. |
| `data-vd-grid` on an element | Check its left and right edges against the generated vertical grid boundaries. |
| `data-vd-occupies` on visible content | Include its bounding box in T6's occupied-area union. |
| `data-vd-space-target` on the stage | Desired negative-space ratio from 0 to 1. Without it, T6 is measured but needs vision judgment. |
| `data-vd-type` on each type level | Include its computed CSS font size in T7. |
| `data-vd-type-scale` on the stage | Minimum adjacent type-size ratio; defaults to 1.25. |
| `data-vd-balance="centered"` or `"asymmetric"` on the stage | Select T5's numeric threshold or report-only vision review. |

T5 uses absolute pixel luminance difference from the frame's median luminance as weight, then reports the centroid distance divided by frame diagonal. T8 uses `sqrt((dL/dx)^2 + (dL/dy)^2)` per pixel; its focal energy share divided by its area share is the reported dominance ratio. Numeric defaults come from the skill, since the course provides no numeric thresholds for these tests. The JSON `source` says `skill default` for those thresholds; when an artifact supplies T6's target or overrides T7's minimum ratio, it names that markup declaration and identifies the default tolerance separately. Missing declarations or boxes that prevent a measure produce `skipped`; measures that explicitly require visual judgment report `not_judged`.
