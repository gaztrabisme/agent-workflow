# scene-engine SPEC.md: objections from a PowerPoint deck editor

Reader: the author of `scene-engine/SPEC.md`. The reviewer edits and presents decks in Microsoft PowerPoint on Windows and Mac, and read only `SPEC.md` and `README.md`. Statements about PowerPoint, python-pptx, Keynote and Google Slides behaviour come from the reviewer's working knowledge. The spec does not contain them, and none were tested for this review.

Severity: **blocking** means the deck would break, a part the spec calls editable would not be editable, or the spec contradicts itself. **non-blocking** means a real problem that does not break the deck or a promise.

| # | Objection | Spec section | Severity | Why it matters | What would answer it |
|---|---|---|---|---|---|
| 1 | No acceptance test opens the deck in Microsoft PowerPoint, but the riskiest parts of the deck are XML written by hand. | §5.4: "Write custom geometry, SVG relationships/fallbacks, Morph transitions, autoplay timing and combo/mixed-axis chart XML with standard-library ZIP/XML patches"; §5.4: "it does not claim Microsoft PowerPoint playback was tested"; §10: "a real PowerPoint open/play test is outstanding" | blocking | python-pptx and LibreOffice accept XML that PowerPoint rejects. A deck can pass AT12 (the round-trip test) and AT13 (the combo-chart test) and still show "PowerPoint found a problem with content… Repair" when opened. After the repair, PowerPoint deletes the chart, video or shape it could not read. | Make opening the deck in PowerPoint without a repair prompt an acceptance criterion, on current PowerPoint for Windows and for Mac. Validate every hand-written part against the ECMA-376 schemas (the Office Open XML standard) in CI. List the PowerPoint versions the deck targets. |
| 2 | The font rules contradict each other, and the fallback turns text into a picture. | §5.4 table: "supported source font must be a PowerPoint cloud font or licensed for embedding"; §5.4: "Rasterize … fonts unavailable to PowerPoint or embedding"; AT14: "retained text stays native"; §10 lists "embedded font" as unverified | blocking | The spec never says how a font is embedded. python-pptx cannot embed fonts, and the schema has no embed flag. Under the rasterize rule, a headline in a non-cloud brand font becomes a PNG I cannot retype. That breaks the promise of an "editable native PowerPoint deck" (§1). If the text stays native instead, my machine substitutes a different font and the text reflows. | Pick one policy: (a) embed fonts, with the mechanism and how it behaves on Mac described; (b) substitute a named fallback font and keep the text native; or (c) refuse to export. Never rasterize live text by default. Report each font and its outcome for each slide. |
| 3 | "Edit Data works" is promised, but the embedded workbook is not designed and no test checks it. | §5.4 table: "preserve series, categories and values so Edit Data works"; §10: "requiring the PPTX writer to create the minimal embedded workbook with standard-library ZIP/XML; verify that this is practical"; §5.4: "The editability acceptance round trip opens the generated file with python-pptx … replaces chart data" | blocking | python-pptx's chart API builds its workbook with XlsxWriter (my understanding, not stated in the spec), and §3 forbids adding another library. The round trip replaces the data through python-pptx, which rewrites the workbook itself, so it never tests the workbook scene-engine wrote. If the cell ranges in the chart XML do not match the sheet, Edit Data in PowerPoint opens an empty or mismatched sheet, or the chart resets when I edit it. | Settle how the workbook is built. Add a check that every range the chart reads from points to cells in the embedded sheet that hold the same values. Add a manual or automated check that Edit Data in PowerPoint (Windows and Mac) opens the right sheet and that editing a cell changes the chart. |
| 4 | Each slide is drawn as it looks at `pptxAtMs`, which defaults to 0, so objects that fade or move in show up invisible or out of place. | §4 schema: `"pptxAtMs": { … "default": 0 }`; §5.4: "The scene's PPTX pose is sampled at `pptxAtMs` (default 0)" | blocking | In an explainer, most layers start at opacity 0 or off-stage and animate in. Drawn at 0 ms, the slide comes out blank or half-built. The objects are still there but have 0% opacity, so I cannot see them to edit them. | Default to the end of the scene, or to the moment every layer is fully visible. Warn when a native object would export at opacity below 0.1 or outside the slide. |
| 5 | The PPTX table lists features that the schema cannot express. | §5.4 table: text "bullets"; §5.4: "Native PowerPoint motion is emitted only for supported entrance presets"; "autoplay timing XML where requested"; the textLayer and videoLayer definitions in the §4 schema have none of these fields | blocking | `textLayer.style` has no bullet or list field, and the schema rejects unknown properties. No field selects an entrance preset, and the presets are never listed. No field asks for autoplay, looping or "play full screen". As written, these promises cannot be built, and I would receive bullet text as broken lines with no animation. | Add schema fields for list paragraphs (level and bullet type), a named list of entrance presets per layer, and video playback options (autoplay, loop until stopped, hide while not playing, start delay). If any of these is out of scope for version one, remove it from the table. |
| 6 | Video in the deck is under-specified. The app-demo layer has no PPTX mapping, supplied video is never normalized, and captions are dropped. | §5.4 table: "Captured or supplied video → Native movie picture, poster frame and autoplay timing XML where requested"; §6: "`--embed-video <file.mp4>` … optionally embed the produced MP4 as a movie object"; §10: "How does PowerPoint store an imported WebVTT file inside a deck?" | blocking | `appDemo` (a captured web-app recording) is stored as a frame sequence, and nothing says it becomes an MP4 movie on the slide. `--embed-video` does not say which slide gets the whole-storyboard MP4 or how big it is. A `videoLayer.src` file supplied as WebM or VP9 is never transcoded to the H.264 profile in §1, so Mac PowerPoint may not play it. The deck video has no captions, which also fails the accessibility check. | Define the PPTX output for `appDemo`: per-layer H.264 encode, poster frame and trim. Name the slide and frame size used by `--embed-video`. Normalize every embedded video to the §1 profile. Either embed the captions or report their absence on each slide. |
| 7 | Scatter charts are promised natively, but the chart schema cannot hold x values, and "stacked" is ambiguous. | §4 chartLayer: `"categories": { "type": "array", "items": { "type": "string" } }`; §4: "chart series value count equals category count except scatter"; kind enum includes `"stacked"` | blocking | A scatter series needs numeric x values for each point, and string categories cannot supply them. The exception to the count rule shows the gap. `stacked` does not say whether it means column or bar, or normal or 100%. Two writers would produce different native charts. | Add `xValues` (numeric) to scatter series. Replace `stacked` with explicit kinds such as `columnStacked`, `columnStacked100`, `barStacked` and `areaStacked`. Add a scatter fixture to AT12. |
| 8 | There are no slide layouts, placeholders or theme, so slides have no titles and changing the theme does nothing. | §5.4 table (text): "Native editable `txBody`"; §4 textLayer: `"fontFamily"` on every layer; the spec never mentions a master, layout, placeholder or theme | non-blocking | Every text item is a free text box carrying a hard-coded font. Design → Variants → Fonts, Reset Slide and Outline view do nothing useful. The Accessibility Checker flags every slide as "Missing slide title", and the slide list and table of contents show "Slide 1, 2…". This is not "broken", but it is far less editable than a normal deck. | Add an optional `role` (title, body, footer) that maps text to layout placeholders. Write the theme's major and minor fonts from the storyboard and use `+mj-lt`/`+mn-lt` (the theme-font references) where the family matches. Let the caller supply a template .potx. |
| 9 | Accessibility metadata exists only for images. | §4: `"alt"` appears only in `imageLayer`; §5.4 fallback "(3) 2× Chromium PNG for unsupported visual effects" | non-blocking | Charts, shapes, SVG pictures, rasterized fallback PNGs, movies and app demos get no alt text, and nothing marks an object as decorative. A rasterized layer that contains words is unreadable to a screen reader. The order in which a screen reader reads the slide (taken from object order in the file) is never stated. | Add `alt` and `decorative` to `layerBase`. Fill alt text on raster fallbacks from the source text. Define the reading order (for example title first, then by `z` or authored order). Run the PowerPoint accessibility rules, or a stand-in for them, in the export report. |
| 10 | Hard line breaks and no autofit rules mean my wording edits reflow badly. | §5.4 table: "Native editable `txBody`; explicit line breaks"; §5.4: "text px map to half as many points" | non-blocking | Line breaks frozen from Chromium's line wrapping split the lines in odd places when I rewrite a sentence. Wrap, autofit and inset settings are not stated, so PowerPoint's default 0.1-inch inset and different text measurement can overflow the box even before I edit. `scaleX`/`scaleY` on text have no stated PowerPoint meaning. | Write paragraphs with word wrap on and no hard breaks (except authored `\n`), zero insets and an autofit mode chosen deliberately. Say how scale on a text layer is applied (to font size or to the box). |
| 11 | Stacking order, grouping and the "PNG plus native text" fallback are unspecified. | §4: `"z": { "type": "integer", "default": 0 }`; §5.4 fallback (3): "preserving separately rendered text as native text where it can remain legible" | non-blocking | Equal `z` values have no tie-break, so Bring Forward and Send Backward start from an arbitrary order. There is no grouping, so a card's background, icon and label move as three loose objects. In fallback 3 the spec does not say whether the PNG leaves the text out. If it keeps it, I see doubled or ghosted text when I edit the native copy. | State the tie-break (array order). Add a `group` field that writes `p:grpSp` (a PowerPoint group). Require fallback PNGs to be rendered with the text hidden, and place the text directly above its PNG. |
| 12 | Slide timing, narration audio and the source of speaker notes are not defined for the deck. | §5.4 table: "Speaker notes → Native notes slide"; §5.3: "Text is metadata for notes"; the schema has no `notes` field | non-blocking | It is unclear whether notes come from `narration.text` or from somewhere else. Scene `durationMs` is not mapped to the slide's "After" advance time, and narration audio is not embedded, so Rehearse Timings and Export → Video from my edited deck lose the pacing of the MP4. | Add an explicit `notes` field (defaulting to `narration.text`). Optionally write the advance time from `durationMs` and embed the narration as slide audio. State which of these are emitted. |
| 13 | Slide numbers and footers are absent. | The spec never mentions slide numbers or footers; §5.4: "One scene produces one 13.333×7.5-inch slide" | non-blocking | With no layout placeholders, Insert → Slide Number does nothing until I rebuild the layouts by hand. Decks sent for review need page numbers. | Write layouts that contain slide-number and footer placeholders and turn them on by a flag, or say this is out of scope. |
| 14 | The deck has no size budget. | AT21: "file is below 256 MB" covers only the MP4; §5.4: "2× Chromium PNG" fallbacks, "SVG picture … plus a Chromium PNG fallback", `--embed-video` | non-blocking | A deck that embeds the full-length 1080p MP4 plus 2× PNG fallbacks and app-demo videos can exceed mail and SharePoint limits, and it opens slowly on a laptop. | Set a deck size target and report each part's size. Compress PNG fallbacks. Warn when the embedded video exceeds a set size. |
| 15 | The spec does not say how the deck behaves in Keynote or Google Slides. | §1: "an editable native PowerPoint deck"; the spec never names Keynote or Google Slides | non-blocking | Recipients open decks in these. Google Slides imports charts without their workbook, drops Morph and may drop embedded video. Keynote's handling of `svgBlip` (embedded SVG), custom geometry and combo charts is unknown. Readers will report these as tool bugs. | State support for each app (supported, degraded or unsupported), and add a manual check or a list of known losses to the export report. |
