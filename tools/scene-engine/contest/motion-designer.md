# scene-engine SPEC.md: motion-design objection register

Reader: the author of `SPEC.md`. Reviewer: a senior After Effects motion designer who makes explainer videos and animated infographics, reading the spec cold. Question asked: can the motion this storyboard expresses come out as anything other than stiff?

Severity: **blocking** means the tool cannot make a professional-quality explainer without this, or the spec contradicts itself. **non-blocking** means a gap or friction that can wait. Rows are ranked most severe first.

| # | Objection | Spec section | Severity | Why it matters | What would answer it |
|---|---|---|---|---|---|
| 1 | The spec builds an animation-adapter system that no storyboard can reach. §5.1 says "Library adapters must use paused seekable timelines (for example GSAP paused timeline/exportRoot, anime.js timeline.seek, Lottie frame setters…)" and AT05 tests CSS animation, WAAPI, SVG SMIL and canvas. But the §4 schema allows only seven layer types (text, image, chart, shape, table, appDemo, video), all with `unevaluatedProperties: false`, and says "Unknown properties are rejected." There is no Lottie layer, no HTML/SVG-snippet layer, no script layer and no adapter reference. | §4 schema `scene.layers.oneOf`; §5.1 last paragraph; AT05 | blocking | This contradicts itself. The adapter contract is the only way to get past the keyframe model's limits (rows 2–8), and the schema shuts it off. Animators hand off Lottie (Bodymovin exports) and GSAP all the time; with this schema, a scene cannot contain anything an animator built elsewhere. | Add a `lottie` layer (src, frame mapping such as `startFrame`/`playbackRate`) and an `html`/`svg` layer that names a registered adapter and its assets. Alternatively, state that adapters are internal-only and drop them from §5.1 and AT05. |
| 2 | There is one keyframe track per layer, not one per property. `keyframe.values` bundles x, y, width, height, opacity, rotation, scaleX and scaleY under one `atMs` and one `easing` ("A keyframe's easing controls the interval from that keyframe to the next one"). The spec never says what happens to a property that is missing from a keyframe. Is it held, interpolated across to the next keyframe that has it, or reset to its base value? It also never says what a layer shows before its first keyframe. | §4 intro and `$defs.keyframe`; §5.1 "Between numeric keyframes, interpolate the property after applying the easing on the earlier keyframe" | blocking | Offset timing inside one object is the basic tool against stiffness. Position should settle with ease-out while scale overshoots and opacity finishes early. With one shared track, every property moves in lockstep on one curve, so everything moves like a PowerPoint "Fly In". The undefined missing-property rule also means two implementations will animate the same file differently. | Give each property its own track (`tracks: { x: [{atMs, value, easing}], opacity: [...] }`), or add a per-property easing override plus a written rule for missing properties: hold, or interpolate between the nearest keyframes that set it. Add an acceptance test (AT) for a sparse-property keyframe. |
| 3 | The set of animatable properties is too small, and there is no anchor point. Only `x, y, width, height, opacity, rotation, scaleX, scaleY` can be keyframed. Color, fill, gradient stops, stroke color and width, `strokeDash` offset (line draw-on), `blurPx`, `letterSpacing`, `fontSize`, shadow, `radiusPx`, `transform3d` and path data are all static. No `anchor`/`transformOrigin` property exists, so the spec never says which point `rotation` and `scale` pivot around. | §4 `$defs.keyframe.values`; `layerBase.effects`; `shapeLayer` | blocking | Explainers rely on line and arrow draw-ons (trim paths), color shifts that mark a state change, blur-in focus pulls, and scale from a corner or a bar's baseline. Without an anchor point, a bar cannot grow from its base and a needle cannot pivot from its hub. | Make every numeric and color style property keyframable. Add `anchorX/anchorY` (or `transformOrigin`) to `layerBase`. Add `trimStart/trimEnd` (path draw-on) to shape layers. Define color interpolation space (for example OKLab). |
| 4 | Layers cannot be grouped or parented, and there is no stagger. Every layer is a flat item in `scene.layers` with absolute coordinates and its own `startMs`. There is no group or null layer, no parent property, no stagger/offset primitive and no reusable animation preset. | §4 `scene.layers`, `layerBase` | blocking | Staggered entrances (a list of six icons, 40 ms apart, each with the same ease) are the most common move in an explainer. Here each one must be hand-authored as separate keyframes with hand-computed times, and any change to the stagger means editing every layer. Without parenting there is no way to move a card together with its label and icon, or to build follow-through (a child lagging its parent). | Add a `group` layer whose children inherit its transform and opacity. Add a `parent` reference on `layerBase`. Add a stagger construct (for example `stagger: {eachMs, from: "start"|"center"|"end", easing}` on a group) and named presets that the compiler expands. |
| 5 | Text cannot be animated below the whole layer. A text layer is one `text` string with one `style` (one family, `fontWeight` limited to `[400, 700]`, one colour). There is no split into lines, words or characters, no per-range style, no range selector, no typewriter or reveal effect and no number counter. | §4 `$defs.textLayer`; §5.4 text row | blocking | Kinetic typography carries most explainers: lines rise in one by one, the key word changes colour on cue, a statistic counts up from 0 to 73%. None of this can be expressed here. The workaround is one layer per word with hand-measured x positions, and that breaks the moment the font or the copy changes. | Add `split: "line"|"word"|"char"` with a per-unit animation and stagger (row 4). Add styled runs (`runs: [{text, style}]`) whose properties can be keyframed. Add a `counter` text mode (from, to, format, easing). Rasterise or flatten these for PPTX as §5.4 already does for other effects. |
| 6 | Charts cannot be animated from their data. The chart layer is static data (`categories`, `series.values`) with only the transforms shared by all layers. Bars cannot grow, lines cannot draw on, series cannot be revealed one after another, and the chart cannot move from one dataset to another. §5.4 only offers "Charts cross-fade during Morph." | §4 `$defs.chartLayer`; §5.4; §7 (render-kit checks charts only as static frames) | blocking | Animated infographics are half of what this tool claims to make. A chart that fades in whole is a slide, not an animation. Building bars from shape layers gets the motion back but loses the native chart, the render-kit chart markup and the editable PPTX data, which defeats the tool's two-deliverable premise. | Add a chart `build` block: `{mode: "grow"|"draw"|"fade", by: "series"|"category"|"point", staggerMs, durationMs, easing, origin: "baseline"}`. Add keyframable data states (`states: [{atMs, series}]`) with interpolation between them. Add value-label counters tied to the same progress. Keep `pptxAtMs` as the final-state pose for the native chart. |
| 7 | Masks and reveals are a boolean with no meaning. `"mask": { "type": "boolean" }` names no mask shape, no target layer, no matte mode (alpha/luma/inverted), no feather and no animation. | §4 `layerBase.effects.mask`; §5.4 rasterisation list ("masks, complex clip-paths") | blocking | Wipes, reveal-from-behind-a-line, text rising out of a clipping box, and an iris onto a detail are core explainer moves. A boolean cannot express any of them, and the spec does not say what `mask: true` does at all. | Replace it with `mask: {source: <layerId> | {shape, x, y, width, height, radiusPx}, mode: "alpha"|"alphaInverted"|"luma", featherPx}`, where the mask's geometry has its own keyframes. Add a clip-rect shorthand (`clip: {top, right, bottom, left}`, keyframable) for the common box reveal. |
| 8 | There is no camera and no scene-level transform. A scene has `id, startMs, durationMs, pptxAtMs, background, layers, narration, captions` and nothing that moves the frame. `transform3d` is a static 16-number matrix inside `effects` and cannot be keyframed. Nothing defines a perspective. | §4 `$defs.scene`; `layerBase.effects.transform3d` | blocking | Push-ins on a detail, pans across a wide diagram and a zoom from overview to a single node are how explainers lead the eye. Here each one means keyframing x, y and scale on every layer in the scene, with matching easing and hand-computed pivot maths. | Add a scene `camera` with keyframable `x, y, zoom, rotation` (2D, and optionally perspective plus 3D position), or a scene-root group (row 4) whose transform can be keyframed. Rasterise this for PPTX at `pptxAtMs`. |
| 9 | Motion cannot be timed to the narration. `wordTimings` is accepted, but §5.3 uses it only to generate captions ("Caption cues … may be generated from supplied word timings"). Every `startMs` and `atMs` is an absolute integer, scene `startMs` is absolute on the deck timeline, and `durationMs` is fixed at the top level. No time can refer to a word, a cue or a marker. | §4 `$defs.narration`, `scene.startMs`, root `durationMs`; §5.3 | blocking | Explainer motion lands on the spoken word: the arrow draws as the narrator says "flows into". When the voice-over is re-recorded or one scene grows by 400 ms, every later scene start, layer start and keyframe must be edited by hand. That makes revision rounds, which are the normal workflow, too expensive. | Allow symbolic times: `atMs` may be `{word: <index or text>, offsetMs}` or `{marker: "name", offsetMs}`, resolved from `wordTimings` at compile time. Let scenes be sequenced (`after: <sceneId>`, or derive `startMs` and total duration from the scene order), so that one change moves everything after it. |
| 10 | Scene transitions offer only a crossfade or a cut, and nothing can stay on screen from one scene into the next. "Scene transitions are explicit overlap and opacity keyframes" and "Scene intervals may overlap for crossfades". A layer belongs to one scene. The `!!` stable name that drives Morph exists only for PPTX. When scenes overlap, the spec does not say which scene draws on top ("scene array order breaks equal-start ties" covers only start order, not layering). | §4 intro; §5.1; §5.4 Morph paragraph | non-blocking | Match cuts, pushes, wipes and a hero element that carries across scenes (a logo shrinking into the corner) are what make an explainer feel continuous. Here they must be faked by keyframing every layer of two overlapping scenes, and how the overlap is stacked is undefined. | Define the stacking of overlapping scenes. Add a transition block between scenes (`{type: "push"|"wipe"|"slide"|"zoom"|"crossfade", direction, durationMs, easing}`). Add a video-side shared-element transition keyed on the same `name` that Morph uses, so the video and the deck tell the same story. |
| 11 | There are no motion paths. x and y are separate numbers, interpolated with the keyframe's easing. There is no spatial Bézier, no follow-a-path option, no auto-orient along the path, and `shape.path` cannot serve as a trajectory. | §4 `$defs.keyframe`; §5.1 | non-blocking | A packet flowing along a curved connector, a plane on an arc, or a cursor curving to a button (the app cursor also has only straight segments with `easing`) all look robotic in straight lines. Approximating a curve with dense keyframes gives corners and a speed that jumps at each keyframe. | Add `motionPath: {path: <SVG d or shape layer id>, startProgress, endProgress, autoOrient}` with keyframable progress, or spatial tangents on keyframes (`inTangent`/`outTangent`). Let `appDemo.cursor` take the same option. |
| 12 | Overshoot, follow-through and secondary motion are blocked. Easing is limited to five presets and a single cubic Bézier, which gives at most one overshoot. §2 and §5.1 reject "history-dependent spring animations", which lumps closed-form springs (a pure function of time, so deterministic and seekable) in with simulated physics. There is no loop or repeat either, so a pulse, a breathing glow or idle drift needs hand-copied keyframes. | §4 `$defs.easing`; §2 Out of scope; §5.1 | non-blocking | Anticipation and settle are what make motion read as weighty rather than mechanical. A spring settle (overshoot then damped return) and an elastic pop are defaults in AE (Ease and Wizz), in GSAP and in Rive, and a single Bézier cannot produce them. | Add analytic easings that are functions of t alone: `{spring: {stiffness, damping, mass}}` or `{elastic/back/bounce: {amplitude, period}}`, and state that they are allowed because they can be sought to any time. Add `repeat: {count|"infinite", yoyo}` to keyframe tracks. |
| 13 | The time grid is fixed at 30 fps and there is no motion blur. The schema sets `"fps": { "const": 30 }`, and `blurPx` is static (row 3). There is no shutter or motion-blur option. | §4 root `fps`; §1 delivery profile | non-blocking | Fast moves such as whip pans, quick slides and spinning icons strobe at 30 fps without motion blur. UI-demo motion is also often delivered at 60 fps. This is less critical while PowerPoint playback dictates 30 fps, but whip transitions will look cheap. | Add optional per-layer or global motion blur (sub-frame accumulation: N samples per frame at seeked times, which works with the seek contract). Treat fps as a delivery choice and allow 60 where the target is not PowerPoint. |
| 14 | There is no way to preview or scrub. The only motion outputs are a full `render` to MP4 and `check`, which sends static key frames to render-kit. No command serves the compiled composition for scrubbing, renders a time range at low resolution, or produces a contact sheet or a motion-curve overlay. | §6 command table | non-blocking | Animators tune timing by scrubbing and replaying 2-second loops dozens of times. A full normalised render on every tweak makes the iteration that removes stiffness too slow, so people stop at the first pass. | Add `scene-engine preview <storyboard> [--from ms --to ms] [--scale 0.5]`, which serves the compiled HTML with a scrubber driven by `__sceneEngine.seek`. Add `render --range` and an optional contact-sheet output. |
